O que aprendi: Conceitos de Versionamento

Ideia principal: quando modificamos um arquivo, criamos um novo estado daquele arquivo. Esse novo estado pode ser entendido como uma nova versão.

1. O que é uma versão?

Uma versão é um estado de um arquivo ou projeto em determinado momento. Exemplo da evolução de um arquivo:

  • Versão 1: página criada → Versão 2: título alterado → Versão 3: menu adicionado → Versão 4: erro corrigido

2. O que significa versionar?

Versionar significa manter um controle organizado dessas diferentes versões para saber o que mudou, quando mudou e qual era o estado anterior.

3. Então, o que é versionamento?

É o processo de controlar e registrar as diferentes versões de arquivos ou de um projeto ao longo do tempo, permitindo acompanhar as alterações e recuperar versões anteriores.

4. Como fazemos isso sem um sistema de versionamento?

Muitas pessoas fazem várias cópias do mesmo arquivo (ex: site.html, site-final.html, site-final-corrigido.html). Isso rapidamente gera confusão sobre qual é o arquivo mais recente e o que mudou entre eles.

5. Que problemas o versionamento ajuda a resolver?

  • Perder uma versão: Evita que uma alteração nova substitua algo que funcionava.
  • Não saber o que mudou: Mantém o histórico das alterações realizadas.
  • Muitas cópias: Acaba com a confusão de arquivos "final1", "final2".
  • Trabalho em equipe: Impede que duas pessoas alterem os mesmos arquivos sem saber o que a outra fez.

6. O que um sistema de controle de versão faz?

  • Registra o histórico.
  • Identifica alterações.
  • Permite recuperar versões.
  • Ajuda na colaboração.

Guarde esta ideia: Versionamento não é “Git”. Versionamento é o conceito de controlar as mudanças. Git é a ferramenta usada para aplicar esse conceito.

Principais Comandos Git

Comando Descrição
git init Inicializa um repositório Git local.
git status Exibe o estado das alterações no projeto.
git add . Adiciona todas as alterações para a área de staging.
git commit -m "mensagem" Grava as alterações salvas na área de staging.
git branch <nome> Cria uma nova branch de funcionalidade.
git checkout -b <nome> Cria e altera para a nova branch.
git merge <nome> Mescla a branch especificada na branch atual.
git log --oneline Exibe o histórico de commits de forma simplificada.
